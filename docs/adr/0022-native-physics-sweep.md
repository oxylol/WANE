# ADR-0022: Run the physics sweep in C++, mirrored from the GDScript world, with the GDScript kept as the reference

- Status: Accepted (the sweep is native; the proc path, hitbox resolution, the VFX budget manager and the lighting pass are not)
- Date: 2026-10-20
- BUILD.md sections:
  - 13, Architecture: "C++ via GDExtension for the physics sweep, hitbox resolution, the VFX budget manager and the lighting pass once profiling demands it";
  - 13, Frame budget: "Input + simulation step 3.0 ms", measured in the stress room by ADR-0020;
  - 13, Determinism and replays: the golden hashes of every fixture stay what they were, on Linux, Windows and macOS;
  - 5, the ground, wall and corner tables: no number changes, the port computes the same answers.
- CLAUDE.md: "C++ GDExtension only for profiled hot paths, and a GDScript reference implementation is kept and tested against it"; rule 1 (the core has no Node dependency), rule 2 (integers in 1/256-unit sub-pixels), rule 4 (a desync is a P0 bug).
- Checklist lines (BUILD.md section 15): "The game holds 60 fps in the stress room on the Deck profile" (CPU half: p99 8.90 to 7.04 ms against 3.0, still not met, see Consequences); the replay and cross-platform determinism lines (unchanged hashes).

## Summary

- `native/src/sweep.cpp` ports `CollisionWorld`'s `walk`, `move_x`, `move_y`, `refresh_ground`, `landing_contact`, `drop_through` and the queries they use, line for line, int64 only (Decision 1).
- The GDScript sweep and `FlatWalk` stay, untouched in behaviour; `CollisionWorld.native` is null for the reference and a `NativeWorld` for the port, chosen at construction by `NativeBackend.use_native()` (Decision 2).
- The native copy of the world is mirrored when it changes: grid by identity and revision, spike inset by value, boxes whole when the list changes, and compared with what was sent whenever `SolidBox.edits` has moved or the simulation starts a tick (Decision 3).
- A call sends the body's fields as integers and gets integers back; `walk` and `refresh_ground` are specialised to send and return least (Decision 4).
- The broad phase is ported too, so the two paths agree even for a body carried far past a move's reach (Decision 5).
- `FlatWalk` is not used on the native path: a native walk costs what a flat-run walk did (2.6 against 2.5 us), `flat_ahead` answers false (Decision 6).
- Proof: random-world differential tests (45,000 ticks of moves, 3,000 corner and crest trials, queries after every tick), the stress run's 64 hashes, 529 golden hashes native on and off, a UBSan/ASan run (Decision 7).
- Measured: stress room input + step p50 3.89 to 2.01 ms, p99 8.90 to 7.04 ms; `physics_bench` per 200 bodies 0.9 to 6.2 ms to 0.6 to 1.1 ms (Decision 8).

## Context

ADR-0020 profiled the stress room and found `CollisionWorld` the first hot path (3.6 ms of the 200 bodies' tick in GDScript; a walker on a flat run 9.6 us a step, on a ramp 35 us) and ADR-0021 built the chain that makes a port safe: the pinned godot-cpp, the `NativeBackend` switch, the parity rules. This ADR is the first port. The task's own rule: the reference is not touched in behaviour, the port is held to it by tests written first, and a desync is a P0.

`CollisionWorld` is 880 lines of integer geometry (tile columns, slope surfaces, swept boxes, corner lifts) plus 410 lines of queries in `CollisionQueries`. It keeps working state in member variables (the hit fields of the last floor query, the swept box) and narrows its list of solid boxes while a move runs. Its callers (`Player`, `Enemy`, `TrainingDummy`, the camera, `Combat`) read and write a `Body`'s fields directly, hundreds of times a tick, so the body stays a GDScript object and crosses the boundary by value.

## Decision

1. **What is native, and how.** `Sweep` (`native/src/sweep.h`, `sweep.cpp`) is plain C++ with no Godot types: int64_t in sub-pixels, `div_floor` spelled out (the reference's `Fx.div_floor`), no float, no unordered container, no signed overflow (the largest product is a few hundred thousand times a few thousand). Each function has the GDScript function of the same name beside it and keeps its order of evaluation, because the hit fields and the nudges are state (`_floor_at` before `_step_up`'s test, `refresh_ground` after a lift). Ported: `walk`, `move_x`, `move_y`, `refresh_ground`, `landing_contact`, `drop_through`, `can_drop_through`, `wall_near`, `touches_spikes`, `touches_hazard`, `region_blocked`, `body_fits`, `point_solid`, `floor_top_in`, `headroom`; and the private ones they need (the tile and box sweeps, `_settle_foot`, `_try_lift`, `_try_duck`, `_edge_run`, `_sweep_walk`, `_swept_advance`, the far-edge landing, the ceiling nudges). `WaneSweep` (`wane_sweep.cpp`) is the thin GDExtension class around it. `NATIVE_VERSION` is 2.
2. **The switch.** `CollisionQueries.native` is a `NativeWorld` or null. A new `CollisionWorld` takes `NativeWorld.create()`, which is null unless `NativeBackend.use_native()` (off, auto or on from `WANE_NATIVE`, ADR-0021 Decision 3). Each public move and query starts `if native != null: return native.x(self, ...)`; nothing else in the GDScript changed, so `WANE_NATIVE=off` runs the code of ADR-0008 and ADR-0020. A test plays both side by side by setting `native` on two worlds (`NativeWorld.create(true)` ignores the switch and asks only for the library). `parse`-time method names are the contract: `test_native_parity.gd` fails if a `WaneSweep` method has no namesake in `CollisionWorld` (the reference is the class itself, not a `NativeRef` twin).
3. **The data, mirrored when it changes.** `NativeWorld._sync` runs before every call and compares: the grid by identity and `revision`, `spike_inset_sp` by value, the box list by length (and identity). A change sends the grid (a `PackedByteArray` copy) or all boxes (six integers each). After that, when the global counter `SolidBox.edits` (bumped by every change of an edge or flag) has moved since the last look, or when `CollisionWorld.begin_tick` (called by `Simulation.step` first thing) asked for a recheck, every box is compared with the integers last sent and the ones that differ are sent with `set_box`. A box holds no link to a mirror (an earlier design linked each box to one world's pending list; that silently desynced a box shared by two worlds, a box replaced or swapped in place, and a box edited after removal, which also indexed out of range). So a box may be in any number of worlds and lists, and removing one leaves nothing behind. The one thing not seen at once is a box replaced by another, or two swapped, in a list that keeps its length: it is seen at the next tick start, or at once after `invalidate()`; a mid-tick replacement is unsupported (tests/unit/core/physics/test_native_mirror.gd pins each case).
4. **The call shape.** GDScript cannot name `WaneSweep` (it may be absent), and `unsafe_method_access` is an error, so `NativeWorld` holds an `Object` and uses `call(&"name", ...)` as `NativeBackend` does. Integers in, integers out: `refresh_ground` returns `on_ground | on_slope << 1 | (ground_tile + 1) << 2`; `walk` takes the box and `nudge_y` (all it reads) and returns `[moved, x, y, nudge_y, contact]` with the contact and `hit_wall` packed in one integer (a walk always sets the ground contact, sets `hit_wall` only to its own direction and touches nothing else); `move_x` and `move_y` take and return the whole contact state (they leave some of it unchanged). The answer arrays are members of the native object, reused, so a call allocates nothing in steady state. Measured on a flat walk: 13 arguments 3.6 us, 7 arguments 2.6 us (the Variant call costs about 0.06 us an argument).
5. **The broad phase is part of the behaviour.** The reference narrows `solids` to the boxes a move can reach (`_narrow_solids`: the reach, the half-width and a tile on every side of the body). That is meant as an optimisation, but a body displaced further than the margin during a move (the random tests found it: a body put below the room, riding up through the solid "outside" in one `_settle_foot`) sees different boxes before and after the displacement. The port narrows identically (`Sweep::Narrowed`, restored on exit), so the two agree on every input, not only on reachable ones.
6. **`FlatWalk` is not ported and is not used natively.** On a flat run the GDScript fast path costs 2.46 us a walk; the native walk 2.63 us (2.3 to 3.0 depending on the box count), so the cache buys nothing and a miss costs more. `CollisionWorld.flat_ahead` answers false on the native path, and the dummy's `_ledge_ahead` asks the native `floor_top_in` instead (same answer: the flat run implies a floor under the leading edge, which `floor_top_in` finds). `FlatWalk` and its tests (run with `native = null`) stay: they are part of the reference and of `WANE_NATIVE=off`.
7. **The proof.** (a) `tests/unit/core/physics/test_native_sweep.gd` builds two worlds from one seeded room, one `native = null` and one native, and plays the same bodies through both: rooms of flat ground with steps, blocks, hazards, one-ways and smooth walls; ramps of all six slope kinds; random tile soup (all twelve kinds, invalid slopes cleared); lips and ceilings from solid boxes; the same with every distance on whole units (so that "exactly as high as the lift" and "exactly at the feet" happen); 1,500 trials of a lip or ceiling beside a body (the corner lift on the ground and in the air, the duck, the slide); 1,500 trials at the crest of each ramp kind with a lip box. Bodies walk like enemies and like the player (lift 8 u, slide 6 u, duck), at 1 sub-pixel to 40 u a tick, fall under gravity, take the far-edge landing, drop through one-ways, are teleported (a tenth of the starts are inside geometry); boxes move, switch, become clingable, come and go, tiles change and the spike inset changes while they play. After every move every field of both bodies (x, y, vx, vy, on_ground, ground_tile, on_slope, hit_wall, hit_ceiling, nudge_x, nudge_y) and the returned distance are compared, and after every tick `wall_near`, `can_drop_through`, `headroom`, `body_fits`, `point_solid`, `region_blocked`, `touches_spikes`, `touches_hazard`, `floor_top_in`. About 160,000 moves in all; the last test counts that the play met every kind of move (a lift, a duck, a slide, a step down, a landing, a ceiling hit). I broke the port on purpose in ten places (off-by-one at a boundary in `step_up`, `ceiling_nudges`, `flat_under`, `swept_advance`, `try_duck`, `settle_foot`, `edge_run`, `floor_at`, the far-edge test) and the suite failed for seven; the three that survive are equalities the generators reach too rarely to count (a step down onto a floor at exactly the feet, a contact exactly at a segment's end, an equal-height tie that only changes which tile kind is reported). (b) `test_native_replay.gd` plays the stress run (3840 ticks, 200 enemies) once on each path: the 64 state hashes and the end hash are equal. (c) The fixtures stage runs 529 fixtures against the one `golden_hashes.txt` with the switch off and on (CI runs both; no golden moved, `Simulation.VERSION` is unchanged). (d) `ci/sanitize_native.sh` builds `sweep.cpp` with UBSan and ASan (no recovery, `-Wall -Wextra -Werror`) and runs 1,000,000 random moves and queries through it, comparing a checksum with a constant. (e) The whole gate passes with `WANE_NATIVE=off` and with auto.
8. **Measured** (this container, 4 cores, template_debug library; the release library is faster). Stress room, `ci/perf.sh --only stress`, best of 3: input + step p50 3.89 to 2.01 ms, p99 8.90 to 7.04 ms (gate 3.00, not met), max 19.96 to 18.22 ms. `tools/bench/physics_bench.gd` with `WANE_NATIVE=off` and `on`, ms per tick for 200 bodies (per call, divide by 200; the loop itself costs about 1 us a body): flat ground 0.9 to 1.4 to 0.6 to 0.85; slopes 3.2 to 5.1 to 0.61 to 0.63; ledges 3.3 to 5.9 to 0.74 to 1.14. The far-edge landing 127 to 17 us a step, the plain air step 30 to 13.5 us. A single walk on flat ground, microbenchmark: GDScript sweep 7.1 us, with `FlatWalk` 2.46 us, native 2.63 us (of which 0.8 us is `_sync`, 0.9 the call, 0.5 unpacking the answer).
9. **CI.** The `test` job runs `ci/sanitize_native.sh` after the build; the `perf` and `perf-stress` jobs now build the extension (they ran the reference before); nothing else changes: the lint job's grep of `native/src` passes, `NativeBackend.EXPECTED_VERSION` is 2.

## Alternatives considered

| Option | Why not |
| --- | --- |
| Port only the moves and keep the queries in GDScript | The moves call the queries (`_floor_at`, `_landing`, `_clear_up`) thousands of times; a boundary crossing for each would cost more than the GDScript did |
| Keep the bodies in native memory and give GDScript handles | Every caller reads `body.x`, `body.on_ground` and so on; a handle API would rewrite the player, the enemies and the camera, and make each read a call |
| A native `Body` class with properties | A property read from GDScript costs about as much as a method call (0.1 us); the player reads a body's fields hundreds of times a tick |
| Mirror the box list by rebuilding it every tick | 200 blockers move every tick in the stress room; one slot per change is 300 small calls, a rebuild is 1,200 integers packed in GDScript |
| Skip the broad phase in C++ (it is only an optimisation) | It is not neutral for a body carried past the margin, and the claim of this ADR is "identical for every input"; narrowing costs a copy of the few boxes near |
| Port `FlatWalk` as well | It saves nothing native (Decision 6); the reference keeps it |
| A float-free fixed-point library in C++ | Everything is already integer arithmetic on int64; there is nothing to abstract |

## Feel reason

None: the numbers of BUILD.md section 5 are untouched and every answer is bit-identical, which is the point. The pillars gain headroom: the simulation's share of a frame in a crowd drops from about 3.9 to 2.0 ms at the median, which is what lets the lighting and the sprites have theirs.

## Consequences

- Easier: a body on a ramp or at a ledge costs what a body on flat ground does (3 to 5 us a move, from 16 to 30); adding an enemy that walks the world is cheap; the reference is one `native = null` away for a debugger.
- Harder: every change to `collision_world.gd` or `collision_queries.gd` is a change to two implementations, and `test_native_sweep.gd` is what says whether they still agree (bump `NATIVE_VERSION` and `EXPECTED_VERSION` together; a changed behaviour on both sides still needs `Simulation.VERSION` + 1 and a re-bless). A developer without the library runs the reference (auto), slower.
- The gate is not met: p99 is 7.04 ms against 3.0, and it is a proc tick (a Kindle cone or Radiance burst raises 40 to 500 procs at 30 us each: `ProcBus.resolve`, the listener call through `ProcApi`, `Combat.nearest_enemy`). That is the next port or the director's design change (ADR-0020 Decision 8, with the hitbox resolution BUILD.md names for C++); the median 2.0 ms already meets the 3.0 ms budget. The `perf-stress` job stays `continue-on-error` (expiry 2026-12-31).
- What the calls cost now: about 150 walkers make two `set_box` calls each a tick (the dummy takes its own blocker out of the world while it moves, then puts it back at its new place), 130 `walk`, 110 `floor_top_in` and 70 `refresh_ground`: around 1 ms of the 2.0 ms median. A native "skip this box" argument, or moving the dummies' patrol into one native call, would remove most of it; neither is done because both change what the GDScript reference has to say.
- The per-tick `_sync` check costs 0.5 us of every call; a push-based version (a tile-edit counter, a spike-inset setter) could halve it, at the price of more state to keep honest.
- First run of the Windows and macOS native builds with this code is still on CI (ADR-0021): the sweep uses nothing the probe did not (int64_t, `std::vector`).
